# Правила проекта dsh-builder

## #0 — Python heredoc
Все патчи через `python3 - << 'EOF'`. Не использовать `sed`, `awk`, `perl` для изменения файлов.

## #1 — `cd` первой строкой
Каждый патч начинается с `cd <директория>`. Не зависеть от текущего пути.

## #2 — Без regexp
Избегать регулярных выражений. Использовать Python для добавления/замены строк (построчно, по точному совпадению подстроки).

## #3 — Диагностировать, а не гадать
Перед фиксом — `ls`, `grep`, `cat`, чтобы увидеть, чего именно не хватает.

## #4 — Не ломать, что работает
Расширять функционал, а не заменять существующий (например, добавлять `android` к списку платформ, а не заменять `process.platform`).

## #5 — Один шаг — один вывод
После каждой команды скидывать результат, чтобы не копить ошибки.

## #6 — Фиксить причину, а не следствие
Например, `tar --hard-dereference` вместо ручного восстановления каждого файла.

## #7 — Проверять целостность
После распаковки — `ls node_modules/.bin`, `ls node_modules/.pnpm | wc -l`, чтобы убедиться, что критичные пакеты на месте.

## #8 — Отладка веб-сервера
Использовать `--no-open` и `--trusted-host` для отладки веб-сервера, чтобы не зависеть от браузера.

## #11 — Построчные патчи
Патчи построчно, с показом изменённых строк.

## #13 — Расширять, а не заменять
Добавлять `android` к списку платформ (через `NARB_TARGET_OS`), а не заменять `process.platform` (иначе сломаются Linux/Darwin/Win32).

## #111 — Всё в YAML
Переносить все локальные патчи в YAML (GitHub Actions), чтобы артефакт собирался без ручных правок.

## #555 — Termux
Все команды выполняются в Termux. Не использовать `/tmp`, не выходить за пределы `~/`.

## #12 — Текстовые файлы: python add line

Для чисто текстовых файлов (`.md`, `README`, `*.txt`, `*.yaml`-комментарии и т.п.) **не** записывай содержимое одной строкой и **не** используй `cat > file << EOF` с текстом внутри heredoc. Вместо этого добавляй текст **построчно** через `python3`: список строк -> `f.writelines(...)`.

Причина: в Termux длинные строки с кавычками, слэшами, `$`, `` ` ``, `\` и юникодом ломаются при передаче через shell/heredoc. Построчная запись через python сохраняет каждый символ как есть.

Шаблон:

```bash
cd <dir> && python3 - << 'PYEOF'
import io
lines = [
    "# Заголовок\n",
    "\n",
    "Текст с кавычками \"...\", слэшами /path/to, $VAR, `cmd`.\n",
]
with io.open("FILE.md", "a", encoding="utf-8") as f:
    f.writelines(lines)
print("[+] appended", len(lines), "lines")
PYEOF
```

Правило распространяется на: `RESURECT.md`, `GOALS.md`, `RULES.md`, любые README и текстовые артефакты.
